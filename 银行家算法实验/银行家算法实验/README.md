## 运行环境

- Python 3.7 及以上
- Windows / macOS 官方安装包自带 tkinter，可直接运行图形界面
- Linux 若提示缺少 tkinter：`sudo apt install python3-tk`

## 运行方式

```bash
python bankers_algorithm.py               # 图形界面（默认，启动即自动生成演示数据）
python bankers_algorithm.py --cli         # 控制台演示模式（无图形环境时使用）
python bankers_algorithm.py --self-test   # 内置自测试（经典教材案例 + 随机批量验证）
python bankers_algorithm.py -n 6 -m 4 --seed 42   # 指定规模与随机种子，便于复现
```

## 实验要求对照

| 实验要求 | 实现情况 |
|---|---|
| n 个客户、m 类资源，界面可输入 | ✅ 界面输入 n（建议 3-10）、m（建议 3-5） |
| 每类资源总量上限随机（5-20） | ✅ `random_instance()` 中 `randint(5, 20)` |
| 每个客户占用资源种类数随机（1-m） | ✅ `rng.sample(range(m), randint(1, m))` |
| 每类资源需求随机（0-资源上限） | ✅ 占用种类取 1~总量，未占用为 0 |
| Allocation 随机生成（不超上限） | ✅ 0~Max 随机，且每类资源已分配总量 ≤ 总量 |
| Need 随机生成（不超过 Max） | ✅ Need = Max − Allocation，天然满足 |
| 查找所有安全序列 | ✅ DFS 枚举（上限 20000 条防 n 过大时卡死，超限时提示） |
| 计算每条序列的资源利用效率并降序排序 | ✅ 定义见下，界面/控制台均按效率降序输出 |
| 图形界面显示 Available / Allocation / Need | ✅ 主界面矩阵实时刷新，含当前资源利用率 |
| 界面输入请求，动态显示成功/失败及原因 | ✅ 失败原因分三类：超过最大需求 / 资源不足需等待 / 将导致不安全状态（回滚） |
| 控制台输出详细日志 | ✅ 界面日志框与控制台同步输出每次请求处理全过程 |

## 关键设计说明

1. **资源利用效率定义**（实验要求“已分配资源占总资源的比例”）：
   按某条安全序列依次执行各进程，记录每个进程开始执行前系统的资源利用率
   （已分配资源总量 / 资源总量），取整条序列执行过程的平均值作为该序列的
   资源利用效率。不同序列中高占用进程完成的先后不同，利用率下降速度不同，
   因此该指标可区分序列并用于排序。
2. **请求处理流程**（教材标准四步）：
   `Request ≤ Need` → `Request ≤ Available` → 试分配 → 安全性检查，
   安全则确认分配，不安全则回滚并拒绝。
3. **初始状态保证安全**：随机生成后执行安全性检查，不安全则重新生成
   （最多 300 次尝试，仍有兜底策略），保证每次实验数据可正常演示。
4. **自测试覆盖**：经典教材 5 进程 3 资源示例（安全性检查、三类请求结果）、
   30 组随机实例（数据合法性、枚举序列与全排列暴力验证一致、效率值域与降序）。
